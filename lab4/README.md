# Лаба 4 (вариант 11)

## Грамматика
* S → aa, S.x := 0  
* S → S aa T, условие T.x > S.x, S_0.x := (S_1.x + 1) · T.x  
* T → ε, T.x := 1  
* T → b T b, T_0.x := T_1.x  
* T → T a b S, T_0.x := max(T_1.x, S.x) + 1  
Язык обозначаем L

## Проверка на КС
Берём регулярный язык R = a^4 bb (abaa)* bbaabb (abaa)* bbaabb (abaa)* bb и K = L ∩ R.  
Если бы L был КС, K тоже был бы КС. Но нет:
* Лемма: если T =>* bb (abaa)^k bb, то T.x = k+1; внутри (abaa)^k правило T -> bTb использовать нельзя, а в каждом шаге T -> TabS нетерминал S обязан свернуться в aa, иначе после `ab` получим не `abaa` и степень (abaa)* сломается, поэтому каждый шаг добавляет ровно один блок `abaa` и увеличивает x на 1; внешние `bb ... bb` делаются двумя обёртками bTb и атрибут не меняют.  
* Правило на параметры: пусть w ∈ K имеет вид  
  w = a^4 bb (abaa)^n bbaabb (abaa)^m bbaabb (abaa)^q bb.  
  Здесь `bbaabb` нельзя собрать внутри одного T в рамках K: в выводе T подстроки `aa` внутри блоков (abaa)* могут появляться только как часть хвоста `abS`, и чтобы остаться в R, каждый такой S обязан быть ровно `aa`, иначе нарушится форма (abaa)*. Тогда внутри одного T между любыми `aa` стоит ровно один `b` в `abS`, и подстрока `bb aa bb` может возникать только как стык между соседними верхнеуровневыми T. Поэтому оба `bbaabb` — это именно стыки вида `bb` как конец T + `aa` из S -> S aa T + `bb` как начало следующего T. Значит эти три степени (abaa)^n, (abaa)^m, (abaa)^q соответствуют трём последовательным верхнеуровневым T в выводе S.
  Так как w начинается с четырёх `a`, вывод S выглядит как `aa aa T_1 aa T_2 aa T_3 ...`, и чтобы после `a^4` сразу было `bb`, нетерминал T_1 обязан выводить строку вида `bb (abaa)^n bb`. Тогда по лемме T_1.x = n+1 и
  S_1.x = (0+1)·T_1.x = n+1.
  Далее:
  - T_2 => bb (abaa)^m bb, поэтому T_2.x = m+1, и условие T_2.x > S_1.x даёт m+1 > n+1, откуда m ≥ n+1; после этого S_2.x = (S_1.x+1)·T_2.x = (n+2)(m+1);
  - T_3 => bb (abaa)^q bb, поэтому T_3.x = q+1, условие T_3.x > S_2.x даёт q+1 > (n+2)(m+1), откуда q ≥ (n+2)(m+1).
* Накачиваем w = a^4 bb (abaa)^p bbaabb (abaa)^(p+1) bbaabb (abaa)^((p+2)^2) bb. Берём разложение w = u v x y z (|vxy| ≤ p, |vy| > 0):
  - если v или y пересекает фиксированные части `a^4`, любой из `bb` или любой `bbaabb`, при накачке ломается регулярная форма R;
  - иначе v и y лежит целиком внутри одной/двух степеней (abaa)^\*, причём если v или y не кратны целым блокам `abaa`, то при накачке снова ломается форма (abaa)^* и слово вылетает из R;
  - остаётся случай, когда накачка сохраняет форму R, то есть v и y добавляют/убирают целое число блоков `abaa`. Тогда при i=0 или i=2 меняются только параметры n,m,q:
    * если меняется только третья степень (abaa)^q, берём i=0: q уменьшается, а порог q ≥ (n+2)(m+1) остаётся тем же (n=p, m=p+1), значит условие нарушается;
    * иначе меняется n и/или m, возможно m и q одновременно, когда `bbaabb` целиком в x: берём i=2. Тогда n и/или m увеличиваются, а правая часть (n+2)(m+1) возрастает. При этом третья степень либо не меняется, и тогда сразу нарушаем q ≥ (n+2)(m+1) из-за того, что у исходного слова было равенство, либо меняется вместе с m, но очень мало: добавка блоков в q ограничена длиной vy, то есть |vy| ≤ p и добавка не больше ⌊p/4⌋, тогда как правая часть растёт минимум на (n+2)·1 = p+2 > ⌊p/4⌋. Значит условие всё равно нарушается. 
Значит K не КС => L не КС.

## Наивный парсер
Функции S(i), T(i) возвращают множество пар (end, x).
* Разбор S: сначала читаем `aa`, затем повторяем блоки `aaT` с проверкой T.x > S.x, обновляем x: (x+1)·T.x.
* Разбор T: либо ε, либо `bTb`; после этого можно дописывать `abS` сколько угодно, атрибут: x := max(x, xS)+1.
Перебираем все ветки, чтобы не зациклиться — любое правило двигает позицию вправо (кроме ε).

## Оптимизированный парсер
* Мемоизация S(i), T(i) через lru_cache.
* Для фиксированного end храним только минимальный атрибут (меньший x не хуже для продолжения).
* Eсли слово не начинается с `aa`, сразу reject.

Оценка: для каждого i множество S(i) и T(i) содержит O(n) пар (разных end не больше n, на end оставляем один min_x). Один вызов parseS(i) перебирает O(n) состояний, каждое смотрит O(n) результатов T(pos+2) => O(n^2); аналогично parseT(i) => O(n^2). Из-за memoization всего O(n) разных i, так что время O(n^3), память на кеши O(n^2).

Почему корректно хранить только минимальный атрибут: в S дальше проверяется T.x > S.x, поэтому меньший S.x только облегчает выполнение условия; в T обновление идёт через max(xT, xS)+1, потому меньший xT не ухудшает последующие значения. Значит при одинаковом end доминирует вариант с минимальным x.
