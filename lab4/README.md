## Грамматика
* S → aa, S.x := 0  
* S → S aa T, условие T.x > S.x, S_0.x := (S_1.x + 1) · T.x  
* T → ε, T.x := 1  
* T → b T b, T_0.x := T_1.x  
* T → T a b S, T_0.x := max(T_1.x, S.x) + 1  
Язык обозначаем L

## Проверка на КС
Берём регулярный язык R = a^6 (abaa)* aa (abaa)* и K = L ∩ R.  
Если бы L был КС, K тоже был бы КС. Но нет:
* Лемма: если T =>* (abaa)^k, то T.x = k+1; в таком выводе при каждом применении T -> TabS нетерминал S обязан свернуться в aa (иначе получим ab + много a и форма (abaa)^k нарушится), поэтому каждый шаг добавляет ровно один блок abaa и увеличивает x на 1.  
* Правило m ≥ 2n+2: w начинается с шести `a`, значит вывод S выглядит как `aa (aaT_1)(aaT_2)(aaT_3)...`. Чтобы не получить `b` до 8-й позиции, T_1 = ε и даёт S_1.x = (0+1)·1 = 1. Далее T_2 => (abaa)^n, T_3 => (abaa)^m, поэтому T_2.x = n+1, T_3.x = m+1. После присоединения T_2: S_2.x = (S_1.x+1)·T_2.x = (1+1)(n+1) = 2(n+1). Следующий шаг требует T_3.x > S_2.x, то есть m+1 > 2(n+1), откуда m ≥ 2n+2.  
* Накачиваем w = a^6 (abaa)^p aa (abaa)^(2p+2). Берём разложение w = u v x y z (|vxy| ≤ p, |vy| > 0):  
  - если vxy пересекает фиксированные части `a^6` или середину `aa`, при накачке ломается регулярная форма R;  
  - если vxy целиком в первой группе (abaa)^p, то при i=2 увеличивается n при прежнем m — нарушается m ≥ 2n+2;  
  - если vxy целиком во второй группе (abaa)^(2p+2), то при i=0 уменьшается m — снова нарушается m ≥ 2n+2.  
Значит K не КС => L не КС.

## Наивный парсер
Функции S(i), T(i) возвращают множество пар (end, x).
* Разбор S: сначала читаем `aa`, затем повторяем блоки `aaT` с проверкой T.x > S.x, обновляем x: (x+1)·T.x.
* Разбор T: либо ε, либо `bTb`; после этого можно дописывать `abS` сколько угодно, атрибут: x := max(x, xS)+1.
Перебираем все ветки, чтобы не зациклиться — любое правило двигает позицию вправо (кроме ε).

## Оптимизированный парсер
* Мемоизация S(i), T(i) через lru_cache.
* Для фиксированного end храним только минимальный атрибут (меньший x не хуже для продолжения).
* Eсли слово не начинается с `aa`, сразу reject.

Оценка: для каждого i множество S(i) и T(i) содержит O(n) пар (разных end не больше n, на end оставляем один min_x). Один вызов parseS(i) перебирает O(n) состояний, каждое смотрит O(n) результатов T(pos+2) => O(n^2); аналогично parseT(i) => O(n^2). Из-за memoization всего O(n) разных i, так что время O(n^3), память на кеши O(n^2).

Почему корректно хранить только минимальный атрибут: в S дальше проверяется T.x > S.x, поэтому меньший S.x только облегчает выполнение условия; в T обновление идёт через max(xT, xS)+1, потому меньший xT не ухудшает последующие значения. Значит при одинаковом end доминирует вариант с минимальным x.
